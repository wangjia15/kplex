## Diagnosis and bounded correction

The desktop source carried owner/page/role, while the same-canvas drop selected the first matching page and role. The preserved actual drag-start → native adapter payload → shared drop callback negative displays R→B and C→B with both B copies in the child role. Dragging the second copy incorrectly opens `mode: relink` with R as origin. Touch/pen occurrence state did not protect this HTML path. Mind Map's earlier separate hierarchy-owner copy guard avoided that particular same-owner branch, but did not establish exact shared desktop-source identity.

The existing `NodeLinkDragSource` now has optional transient `occurrence: {id,current,relationship?}`. Relationship context contains the canonical origin reference/incarnation, role, direction, type and physical definition. The source ID comes from the actual rendered DOM; the canvas/native file/document/gesture lifetime stays with its existing owner. Only one real primary incoming edge can provide removal context. Extra cross-links, descendants without a primary scene edge and ambiguous incidence gain no such authority.

The drop resolves one exact current occurrence, rechecks canonical/native identities and compares the current incoming relationship with the capture. Only matching same-canvas source and explicit target origin can relink. A stale/ambiguous context may fall through to independently valid additive creation/navigation; it cannot remove another edge. Cross-canvas imports never inherit source relationship removal authority. Stale captured sources cannot authorize structural moves. Native occurrence-editor dragover and drop still yield before canvas consumption. Target gate/area origins now check actual native-file identity as well as canonical scene identity.

There is no new backend, writer, graph store, global occurrence registry or portable view API. Old adapter callers still export usable canonical links but have no removal authority without the optional proof. Classic's ordinary real primary relationship can still relink; descendants remain exact, copy-only exports. Root navigation, branch toggles, separate editor actions, parent areas, `dropRole`/`dropOrigin`, `canEditAreas`, cross-links and quiet settings failure ownership are retained.
