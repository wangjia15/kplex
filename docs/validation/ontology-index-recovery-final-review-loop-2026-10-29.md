## Requested corrections

The fourth review reproduced an introduced sibling regression against unchanged-base controls: opening a capped folder surface reduced a note's eligible siblings from ten to nine, and could hide both remaining siblings when earlier members already occupied its direct zones. It also reproduced missing-metadata coupling between surfaces sharing a Markdown center.

- **Sibling candidate pool.** The existing Classic projection now exposes its mathematical candidate bound: four capped direct zones can occupy at most `4K` nodes plus the center, so a sorted parent prefix of `5K + 1` suffices to retain the first `K` eligible siblings. The GraphIndex caller requests that bounded pool from the existing native folder compiler. With the supported maximum `K = 300`, at most 1,501 child candidates plus center/parent survive; there is no complete folder semantic graph or recursive subtree retention. Private candidate windows remain bounded by the pool plus one 64-member chunk. The folder itself still displays `K` rows, and only actual visible rows admit optional nested-folder gate work. The pool is prepared independently of the current sibling toggle, so another surface/navigation cannot inherit an insufficient old cap.
- **Partial metadata recovery.** Only warm selected-owner recovery may supply required metadata paths. Ordinary count covers retain their strict all-contributor requirement. Unavailable or guarded nonrequired peers are omitted, including every incident relation and its evidence, after canonical resolution; unknown overrides cannot be shown as inferred pairs. A selected unavailable owner still rejects its surface, preserving any healthy previously published cover. Partial results certify neither complete neighborhoods nor relationship writes. The attempt receipt includes primitive file/availability observations, so unchanged missing inputs are not polled but newly available metadata is re-admitted.

The increased retained candidate bound is intentional and verified with occupied-zone and display-limit cases; the old `K + 2` retained-page assertions were replaced with the new proven `5K + 3` bound. Existing display, ordering, zero-body-read, zero-inventory, identity, timing and compiler limits remain asserted. Direct HostMetadataPreview consumers without an explicit candidate request keep their original 300-child maximum.

## Additional findings fixed during repeated review

I repeated “Evaluate the regression risk of this PR” against the updated patch and its publication/lifecycle boundaries, then fixed the following concrete issues before final acceptance:

1. **Late source metadata replacement.** Native identity/stat checks alone did not close an earlier source's metadata object across later awaited collectors. A final linear metadata-identity pass now accompanies native validation, without adding whole-cover checks to record guards. A new race case replaces the earlier metadata during a later body await and rejects publication.
2. **Exact native connection counts.** A bounded folder pool could replace a complete visible neighbor total (52 instead of 91 in the 90-child fixture). Native parent/child gate certificates are disjoint and now supply the exact visible total. Structural revisions and visibility signatures still fence those certificates.
3. **Body-discovered endpoint precedence.** A requested body can reveal a physical target before host aggregate links name it. Canonical decoding now admits that selected anchor's direct endpoint metadata into the same private compilation, preserving the opposite note's document-property precedence. Newly discovered nonselected peers cannot recursively expand the graph. Source/record/byte limits and native/metadata finality still apply.
4. **Changed native incarnation during an attempt.** The new availability retry initially also retried silent rename/replacement changes. Existing fence tests caught this. Only a metadata availability change on the same native incarnation may re-admit without a notification; silent physical changes retire the attempt. Both original rename/replacement tests retain their assertions and pass.

A private native folder cover also fences both candidate capacity and visible-row limits; lowering the display limit during a yield cannot publish an old-row receipt. Count-only folder proofs remain independent of display-limit changes.

The first endpoint-precedence test incorrectly assumed Hidden applied to the opposite direction. Established core tests preserve directional Hidden, so the regression instead uses opposite-note Parent metadata and its independently verified inverse baseline. A metadata-arrival observation wrapper also needed the real source reader bound to its owning instance. Neither setup error is retained as a baseline or counted as an implementation pass.
