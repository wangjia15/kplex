## Implementation boundary

`GraphIndex` still owns native rename identity, publication, search and lifecycle. `remapGraphEndpoint()` extracts the existing coordinate/evidence mutation and resolves both directions against that exact owner's page map. The existing evidence store and resolver preserve precedence and raw provenance; no second classifier or rename coordinator is introduced.

Retained semantic/local/cached read scopes remap only pages bound to the exact moved `TFile`. The page object and alias facets survive; filename/path and affected reverse keys change synchronously. Existing file-tree helpers also repair a moved file's parent inside scopes which already expose ancestry. Old source/count certificates are retired rather than fabricated at the new path. Exact positive and negative relationship covers retain their coherent reads at the new coordinates while their captured write authority closes. This prevents an already removed relationship from reappearing merely because its endpoint was renamed. Presentation notification follows the complete per-file mutation. Parent-only folder events also capture affected retained endpoints before yielding, without a Vault inventory.

A repeated native eager-mode run additionally caught an actual known-facet regression: closing a remapped requested scope's source proof selected an older complete graph and lost its known `Stable alias`, changing the title to `Stable title`. Remapped scopes now retain read preference over the older graph, including sparse physical facets, while current scopes still replace them and all source/write checks remain closed. A real IndexedDB regression builds/persists/restores the old graph, prepares newer aliases through the actual source owner, and uses the existing cached-startup retention boundary. Removing only the read-preference correction makes the regression fail with title `New`; the candidate passes with `Stable alias` and no write authority. This deliberately models the cached-read boundary rather than claiming a complete startup simulation.

Further native repetition caught a case-only rename with zero materialized neighbors. Synthetic owner attribution showed no requested scope and an older canonical Origin whose only neighbor was the obsolete Modal ghost; the newer host metadata preview supplied the real moved-file link before rename, then provisional retirement discarded it. Rename now preserves previews bound to the exact moving TFile and remaps them with the same helper. Build request tokens are still retired, and ordinary non-rename retirement is unchanged. A deterministic regression publishes a real host preview over an older canonical ghost, dispatches the real source rename listener and confirms one current-coordinate neighbor, preserved alias and closed write authority. Removing only preview retention makes it fail with zero neighbors.

Ordinary acquisition and metadata convergence decide whether remaining raw old-name references support a ghost. The fix does not rewrite aliases, properties or note contents, remove supported ghosts, migrate persisted schemas, or schedule a whole-vault rebuild. Existing path/stat/current-Vault-identity fences continue rejecting late pre-rename reads.
