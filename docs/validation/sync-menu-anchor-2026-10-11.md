# Sync and Sidecar menu anchors — 2026-10-11

PR [#138](https://github.com/zsviczian/kplex/pull/138) implements issue [#119](https://github.com/zsviczian/kplex/issues/119). The sync toolbar button dispatched an action without a mouse event, so the menu always used the pane's top-left fallback. The Sidecar position button followed the same route.

Both controls now retain instance-local refs. The UI reads their live rectangles after action dispatch and passes coordinates, the owning document and the owning leaf to the existing tracked Obsidian Menu. Hidden, detached, foreign or offscreen controls use a bounded fallback within their visible Plex. Detached or invisible Plex roots cannot open a menu. Obsidian retains menu-size clamping, dismissal and focus ownership. No DOM/event capability enters ActionManager; no pointer event or coordinate is retained. Existing sync/Sidecar choices, action IDs and graph/settings semantics are unchanged. Settings receives its pointer event directly and is outside this fix.

Native acceptance exposed an existing disposal gap: an open menu survived the originating Plex's migration into a popout. The existing host surface registration now captures its rendering document and dismisses its current leaf/document menu during release. Stale registrations, another leaf and a successor in another document cannot close the new menu. Native-hide cancellation timers/listeners are retired as well. A production-callback regression failed before this fix and covers those ownership boundaries after it.
