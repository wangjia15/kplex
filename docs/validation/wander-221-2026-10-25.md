## Failure and correction

[Issue221](https://github.com/zsviczian/kplex/issues/221) reports that Wander starts without selecting or navigating. Its support report shows a usable requested neighborhood with a non-authoritative corpus following partial snapshot recovery. Global completeness and gate-count completeness are separate from navigable local incidence.

The shared renderer's readiness callback required every rendered center gate to have complete/local numerical coverage. A prepared local scene with canonical navigable occurrences and unavailable numerical counts therefore waited until the controller's unavailable timeout. This is reproduced through the actual Compass renderer and Wander controller before the correction. Rooted/optional-port views also cannot rely on attention being rendered as a center-role occurrence with every physical gate.

The callback now checks the existing cache-only `GraphIndex.viewScopeCoverage(activePath).prepared` certificate and exact current canonical attention identity. It does not acquire, retry, scan, parse or query gate counts. Displayed candidates, exact occurrence/native-file preflight, shared selection/reveal, existing navigation, pacing, motion, Zen and cleanup owners remain. Rooted Mind Map keeps its root while attention moves. Unprepared, failed, hidden, disconnected, stale or interacting/transitioning scenes still decline. Numerical counts remain unknown; they are not replaced with invented zeroes.

Wander is shared base behavior for all view definitions. No view-ID exception or new capability is required. The regression iterates the actual production registry plus the public columns example, which omits editor and gate-related capabilities. Adding/replacing a production view exercises the same expectation automatically. Facets will retain this regression as its presets/layout evolve.
