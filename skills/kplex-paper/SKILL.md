# 论文精读进 K-Plex

交付一篇有证据的主精读笔记、被引论文逐篇独立的摘要笔记（关键工作补详解）、全部参考文献清单，以及可导航的 ontology 网络。以论文原文为事实依据，区分作者结论、自己的解释与待核实信息。

## 1. 定位环境并读取契约

先读 [references/contracts.md](references/contracts.md)，写笔记时读 [references/templates.md](references/templates.md)。

- Vault 优先取用户本次指定路径；其次使用当前 Obsidian 工作区、可用 CLI 的 vault 列表或本机 Obsidian 的 vault 注册记录。核实候选目录有 `.obsidian` 和 `.obsidian/plugins/k-plex`，多个候选时结合会话与当前打开的 vault。仍不唯一才问用户，不因某个硬编码路径存在就选中，也不新建 vault。
- 只读目标 vault 的 `.obsidian/plugins/k-plex/data.json`，必要时读插件 manifest 和现有论文样例。只提取任务所需字段，不输出密钥或整个配置。记录 `paperFolder`、`paperIdFields`、`paperReferenceField`、`noteTypeField`、`paperNoteType`、`hierarchy`、论文与 Section 显示开关。数据缺失时说明使用插件默认值的哪些部分。
- 文件夹沿用配置或现有组织；未配置目的地时沿用用户上下文/原生新建文件夹规则，不能把空的 `paperFolder` 当作 `Papers`。资产放在目标论文目录的 `assets/<稳定标识>/`。
- 列出阻碍功能的设置与建议，按用户已有授权操作；没有授权时通过原生界面指导用户开启，不静默改写 `data.json`、ontology、工作区或插件状态。

## 2. 取证、身份匹配与阅读范围

1. 获取 PDF/HTML 正文及元数据。先用用户文件、出版商/arXiv 原文；再用可用的 Semantic Scholar/OpenAlex 等补元数据与引文。网络/API 不可用时继续处理已取得内容，记录缺口。不要假装已联网或已读全文。
2. 为每份来源记录 URL/本地路径、版本、获取日期、页码或章节。扫描件先 OCR；核对关键公式、表头和数字，OCR 不确定处显式标注。
3. 用已核实 DOI（小写、去 URL 包装）、arXiv（去版本号但记录所读版本）、S2 ID 匹配现有笔记；再用规范标题 + 第一作者/年份人工核对。已有同一论文即更新它，不因重跑生成 `(2)`。ID 冲突保留原值并报告；无 ID 的论文仍可记笔记，不能编造 DOI/arXiv。
4. 在正文“来源与阅读范围”明确 `full-text`、`abstract-only` 或 `metadata-only`。摘要不可得时写“未取得原文摘要”，不把自己的总结冒充 Abstract；翻译只针对已取得原文。仅摘要时交付受限笔记并列出未完成的图表、实验和全文阅读项。

## 3. 主论文深读与真实图表

全文可得时按论文实际结构覆盖问题、相关工作、方法、实验、讨论和结论，不只写通用摘要。每节给出主张、证据位置、解释及其作用；方法拆到输入/输出、步骤、符号/公式、假设与代价；实验说明数据、比较对象、指标方向、设置、主要数字、消融和适用边界。区分相关性与因果、显著性与单次结果，不自行补实验。

- 先清点原文 Figures/Tables（含附录是否覆盖），再嵌入支持方法与主要结论的真实图表；未嵌入项保留编号、位置、原因。用户要求全部图表时按清单逐项完成或标明不可取得。
- 用 PyMuPDF 等渲染/裁剪 PDF 页，优先可核对的高分辨率局部；裁剪不可靠则用整页并标注。表格需保留表头、单位、脚注，跨页表不能只截半张。逐张打开检查清晰度和裁剪范围。下载文件放独立的新目录，脚本与下载分开，Python 读下载件用 `python -I`。
- 每个嵌入后紧跟独立题注行，如 `*Figure 2: <可核实原题注>*`；另起段写“解读：…”和“来源：PDF p. 5，Figure 2，裁剪/整页”。题注未取得就明确“原题注未取得”，不推测其原文。图表编号沿用论文，文件名可用 `fig-2.png` / `table-1.png`。
- 高亮用 `==原文短句==^[中文评论]`，正文另列页码/节号。评论解释推理和限制，不重复原句。无原文时可高亮自己的句子但标“读者概括”，不得伪装引文。空白说明节不用为了面板而硬塞高亮。
- Mermaid 可作补充机制图，标注“读者绘制”；它不替代原论文图片，不会自动成为 K-Plex 原生 Mind Map 或图片面板。

## 4. 全部引文清单与关键引文笔记

- 解析完整 References，保留每一条的编号、题名、原始书目信息、可核实 ID/链接、在本文中的用途及处理状态。在线列表要翻页至终点；和 PDF 清单对照，区分本文所引与后续引用本文的文献。数量不齐就报告“已取得 n / 总数未知或 N”，不可写“全部完成”。
- 默认按完整清单为每篇被引论文建立或复用独立摘要笔记，不递归展开这些引文自己的参考文献。先完成身份核实和摘要层，再挑约 5–10 篇直接支撑方法、核心理论、主要基线/数据集或争议的工作深入解释引用上下文并补核心配图。文献很多时分批写入并记录进度，不能擅自把任务缩成只处理关键几篇；用户明确指定子集时按其范围执行。取不到摘要的条目可建立明确标为 metadata-only 的书目笔记，统计为“摘要待补”，不能计作摘要已完成。未核实或未落盘项留在清单并报告，不用虚构链接制造已完成假象。
- 每篇关键引文单独核实身份，获取其真实 Abstract 并中译，说明其贡献和与主论文的关系，标出主论文引用位置。拿到被引论文全文时可补真实核心图及题注/解读；只有摘要时不强求图片，也不用首页截图假充 Figure 1。
- 把知识关系映射到目标 vault 已有字段。默认 `References` 是引用方向（主文 → 被引文），论文功能正常启用时它属于 parent ontology。默认每对论文只生成一种显式图谱角色：一般引用放 References；若经证据判断需放 Friends/Challenger，则该对不再同时写 References/Parents，引用事实留在完整书目清单。Parents 只用于额外核实的奠基关系，不因为“引用了”就叫“奠基”或“挑战”。不要给所有引文额外批量反写 Children；反向图谱由插件解析。已有多角色关系保留并报告，不擅自清理。
- 若自定义引用字段已经属于其他 ontology 角色，保留现状并说明冲突。未获配置授权时先保留普通书目链接；不能偷偷注册字段、移动角色或承诺固定 Compass 方位。

## 5. 安全重跑与写入

采用现有命名惯例；新论文可沿用 `paperFileStem`（第一作者末词 + 年份 + 标题，净化并限制 90 字符）。只有确认不同论文同名才加后缀。链接采用已解析的 vault 相对路径，YAML 数组元素引用为 `"[[目录/笔记]]"`，用 YAML 序列化器处理冒号、引号、多行文本。

写前读原文件；补缺失元数据和缺失内容，不覆盖用户标题、笔记、高亮、未知 frontmatter 或既有关系。用稳定的小节标题、图编号、规范论文身份定位已生成块；能识别归属时只更新该块，无法安全区分时保留并报告建议。关系与清单按论文身份去重，资产复用同一稳定路径；不删除用户图片。写前检查文件自读取后是否变化，变化则重读合并，不盲写。通过 K-Plex 原生创建流程时等待其模板自动化完成，不能用固定延时替代。

## 6. 使用原生功能并验收

按 [契约说明](references/contracts.md) 指导实际可用操作，不调用猜测的 CLI/API：

1. 以主笔记为中心，在 Compass/Mind Map 展开原生章节树，确认方法、结果等节的高亮与图表面板有内容。核对 `sectionShowContent`、`sectionShowHighlights`、`sectionShowFigures`，而非声称普通全文都会显示在面板。
2. 展开图表大图并钉住，与 Section 高亮评论并读；图卡支持移动/调整大小。Pins 是论文书签；同步到钉住的原生笔记 leaf 是另一功能，均不等同于图卡。朗读依赖可用的内置阅读器/语音环境，不承诺所有设备自动发声。
3. 切原生 Mind Map 沿现有 ontology 阅读引用分支与章节；它是插件布局，不是另存 Mermaid 图片。需要并读 PDF 时通过原生 Sidecar 打开 PDF；仅写 `pdf` 属性不等于 Sidecar 自动打开。
4. 从 `presets/paper-roles.json` 导入 Facets（设置 → K-Plex → Canvas behavior → Views → Facets → Manage presets → Import）。导入预览后由用户选择该预设；导入本身不选中视图。该预设按 `Paper role` 属性分类，缺失值保持 Unassigned，多角色冲突保持 Conflicting，不加笼统 Note type 兜底。分类仅覆盖当前 Plex 候选，非全 vault 文献查询。
5. 如需要只看论文，使用 Graph Lens 的 Simple builder 对真实样式属性取值过滤；Code 示例 `note["Note type"] == "Paper"` 仅适用于确有此属性的 vault。自定义字段需相应替换。

验证 YAML 可解析、引用/图片路径实际存在、题注与原文相符、所有生成短引文有来源、图表与参考文献覆盖数准确、重跑没有重复笔记/小节/关系。没有原生 Obsidian 工具时只报告文件检查，不把源码契约检查说成 UI 验收。

交付：创建/更新文件清单，全文/摘要阅读级别，已处理/总引文与图表数，关键引文选择理由，已验证和待用户操作的功能，以及剩余缺口。技能维护者可在 K-Plex 仓库运行 `node --test skills/kplex-paper/scripts/validate.mjs` 验证实际源码契约；[evals/evals.json](evals/evals.json) 是有限任务评测提示，不能把静态契约测试当作模型生成质量评测。
